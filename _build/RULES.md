# 久留米興業サイト 制作ルール（公開前チェック）

公開・push・確認用ページの更新の前に、必ず `node _build/qa.js` を実行し「OK」になってから出す。

## 1. 写真
- 同じ写真をサイト内で2回以上使わない（ページをまたいでも不可）。HERO・カード・背景画像・アバターも数える。
  - 「サイト」の単位：パターン①×デザイン①（6ページ）、パターン②×デザイン①（6ページ）、比較用TOP 4案（各1ページ）。
  - 比較用TOPは同じ構成パターンのTOPと同じ写真を使ってよい（デザインだけを比べるため）。ただし1ページの中での重複は不可。
  - トリミング違いの同じ写真（ceo と ceo-wide、field-sidewalk2 と field-team-back、office-pc と office-pc-wide）も同じ写真として数える。
- 写真が足りないときは使い回さず、写真なしのカード（`.link-card.no-media`）や文字だけのレイアウトにする。
- 作業員（現場職）の個人紹介には、顔が見えない作業中の写真を使う。
- 代表の写真は、代表インタビュー資料の写真から使う。
- 工事黒板に他社名が写る写真は、自社施工の実績として使わない。

## 2. 表記
- 画面に出典・情報源を書かない（「求人票より」「採用ブログ」「出典」「公式サイトの掲載表記」など）。根拠の管理は確認用ページ側で行う。
- 制作メモ（CMS連携予定など）は公開画面に出さず、`.review-note`（確認用のみ表示）にする。
- 見出しは自然な日本語にする。体言止めや倒置で意味が通りにくくならないか読み返す。
  - 例：×「一日には、いくつもの役割がある。」→ ○「1日の中でも、いくつもの役割がある。」
  - 例：×「夏も現場へ」→ ○「夏の暑さの対策」（大変さを書くときは、会社の対策とセットにする）
- 「1日」「一日」は「1日」に統一する。

## 3. コントラスト
- 本文は背景とのコントラスト比4.5以上、大きい文字（24px以上、または18.6px以上の太字）は3以上。
- 濃い背景（`.navy-band` など）の上に白いカードを置くときは、カード内の文字色を必ず濃色に戻す。
- 薄いグレーの文字は使わない。補足文も `#4d5c70` 程度より濃くする。

## 4. 自動チェック（qa.js）で見ているもの
写真の使い回し（サイトごと・ページ内）／コントラスト不足（1440px・390px）／表記NGワード／横スクロール（1440・1024・390・360・320px）／画像切れ／ページ内・ページ間のリンク切れとアンカー切れ／H1の数／JSエラー

## 5. 構成×デザインの比較
- 既存のパターン①×デザイン①のURL・HTMLは変えない（比較切替の読み込み2行と html の data 属性だけを追加）。
- デザインごとのCSSは `assets/compare/*.css` と `assets/p2.css` に分け、`[data-structure][data-design]` にスコープする。単なる色違いにせず、レイアウト・写真配置・文字組み・動きを変える。
- 比較切替は `assets/compare/switcher.js / switcher.css` の独立部品。CMS移植時は読み込み2行を消すだけで外せる状態を保つ。
- 同じ構成パターンのデザイン②・③は `_build/cmp_copy.py` の同じ文章・写真・リンクを使う。

## 6. 配色（2026-11-06〜 オフィス由来のブルーグレー）
- 色の正本は `config/themes.json`。ビルドで `assets/theme.css`（`--kk-*` 変数）と `assets/theme/presets.js` を生成する。CSSに新しいHEXを直接書かない（デザインごとのCSSは `--kk-*` だけを使う）。
- 大きな面はブルーグレー／白、ロゴの紺は見出し・細線・主ボタン、ライムは点・短い線・小さな強調だけ。濃紺の全面背景や、ライム地に白文字は使わない。
- ロゴ画像の色は変えない。写真の上に文字を重ねるHEROは使わない（文字は独立した面に置く）。
- デモの「配色を調整」は閲覧者のブラウザ内だけ（localStorage「kurume-demo-theme-v1」）。全員の既定色を変えるときは、書き出したJSONを `config/themes.json` に反映して再ビルド・再デプロイする。
- 品質チェックは既定色に加え `QA_QUERY="?palette=office-neutral"` などで3プリセットとも確認する。

## 7. ファーストビュー（2026-11-06〜）
- ファーストビューは **CMS標準セクションで作る**。TOP＝「721 Mainvisual Responsive Slider」に写真1枚とキャッチコピー（ラベル・H1・リード・対応工事のテキスト）を一緒に載せる。下層＝これまでの「734 H1 Center」。独自HTML（方式C）にしない（`_build/cms_hero.py` の top_hero を使う）。
- **ボタン・リンクを置かない**。画像と文字だけ。
- TOPの文字は写真の上に置くが、必ずネイビーの暗幕（CSSのグラデーション）を敷き、写真が明るくても文字のコントラスト4.5:1以上を保つ。`.fv-slide` の背景色はネイビーにしておく（qa.js のコントラスト判定に使う）。
- デザインの違いはCSSで変えられる範囲（文字位置・余白・文字サイズ・揃え・写真の高さ・暗幕の濃さ）に留め、セクションの構造を作り変えない。大幅な変更が必要なときは、作る前に確認する。
- qa.js が「H1のあるセクションの data-cms-id に734／721があるか」「方式Cでないか」「a・buttonが入っていないか」を自動で確認する。

## 8. 配色セットとカラーパレット
- 配色セットは `config/themes.json` の presets に追加する（全17色を持たせる）。パネルのカードと `?palette=キー` の両方に自動で出る。
- 追加したセットは、qa.js を `QA_QUERY="?palette=キー"` で回し、全ページ「OK」になることを確認してから公開する。
- パネルのカラーパレット（色見本）は theme.js の SWATCHES。クリックすると「色を当てる場所」で選んだ色（または直前に触った色の行）に適用される。保存先はそのブラウザだけ。

## 9. 年表・ラベルと記号の余白
- 年表など「文字＋点（●）＋線」の組み合わせでは、文字と点の間に16px以上、点と本文の間に24px以上の余白を取る。文字列は折り返さない（white-space:nowrap）。「これまで」「これから」など長いラベルでも詰まらないか、1440px と 390px の両方で確認する。

## 10. 写真の量と文章量（2026-11-06〜）
- 建設会社のサイトなので、文字だけのセクションを続けない。本文が250字を超えるセクションには写真を1枚入れる（構成②・ビジョン系は特に優先）。写真は `.p2-shot`（横長1枚）で、セクションの見出しの直後に置く。
- 写真を入れたセクションの本文は短くする（見出し＋2〜3行を目安）。FAQ・募集要項など情報として必要な部分は削らない。事実を足さず、削る・言い換えるだけにする。
- 新しい写真を受け取ったら `python3 _build/photo_dupes.py` で既存写真との重複を確認する。ほぼ同じ写真（同じ元写真・トリミング違い）は追加しないか、qa.js の ALIAS に登録する。
- 現場作業員は顔が写っていない写真だけを使う。マスク等で一部隠れていても目元が見える写真は使わない。

## 11. 手描きのトーン（2026-11-09〜、デザイン①の12ページ）
- 発想は「路面に吹き付けるスプレーの筆跡」と「社屋の手書き看板」。写真は白黒、色はライム（オフィスの椅子）と紺（ロゴ）の筆跡だけ。日本語の大見出しは太い角ゴシック（Dela Gothic One）。明朝・筆文字は使わない、英字ラベルはマーカー文字（Permanent Marker）。フォントは assets/fonts に同梱。
- 筆跡は assets/ink/*.png をマスクにして背景色を塗る（assets/ink.css）。文字は必ず筆跡の面（紺または白）の上に置く。ライムの筆跡には文字を載せない（配色セットによってはコントラストが不足するため）。
- ファーストビューの写真は現場・オフィスを主役にする。代表一人の人物写真をメインビジュアルに使わない。
- TOPの721は、写真・筆跡・手書き文字を1枚の画像に仕上げて登録し、H1はテキストで別に持つ（_build/cms_hero.py の ink_hero）。
- 本文側も同じトーン：写真はすべて白黒、セクション見出しは Dela Gothic One、セクションの境目は筆跡のふち、紺の面（navy-band）は白文字、写真の角にライムの筆跡、カードの上は紺の筆跡、主ボタンは紺の筆跡の形。新しいページもこの assets/ink.css のまま作る。
- メインビジュアル（TOPの721・下層のヒーロー）は基本カラー。元から白黒の写真はメインに使わない。本文の写真は白黒で、カーソルを合わせると色が付く（タッチ端末では白黒のまま）。
- パンくずリストと、ページ内の目次ボタン（採用情報の「数字で見る」など）は表示しない。

## 12. 第3パターン（写真の色を活かす・2026-11-09〜）
- pattern3/design-a|b|c（_build/p3_build.py、CSSは assets/p3/）。TOPは独自本文、下層5ページは構成①の下層をそのまま流用し、assets/p3/pages.css で3デザインに分ける。見出しは通常のゴシック（Noto Sans JP 700）で、極太書体は使わない。手描きトーン（ink.css）は読み込まない。写真はカラーのまま、暗幕・フィルタなし、文字は写真の外の無地の面に置く。
- A PHOTO FULL（写真全面）／B GALLERY（白い誌面に大小のグリッド）／C SITE COLOR（重機の黄・コーンの橙・作業着の紺を面で使う。黄・橙は固定色、文字は紺）。

- パターン③のTOPは、パターン①のTOPと同じ9セクション（文言・リンク・写真の役割とも同じ）を持ち、メインビジュアルと「見せ場」1セクション（A 全幅写真／B 写真のグリッド／C 現場の色）だけをデザインごとに変える。内容を減らしてデザインの差を出さない。QAが見出しの欠けを検出する。
- パターン③の配色は assets/p3/tone.css（全ページ共通・配色パネルでは変えない固定色）。背景は色みのない白・グレー・紙色にし、青みのある面は使わない（写真の黄・橙・緑が濁る）。画面で色を持つのは写真だけ、差し色は写真から取った1色を線や小さな面に。A＝白と黒（差し色は重機の黄）／B＝生成りの紙と紺のインク、写真は白いマットのプリント／C＝重機の黄とアスファルトの黒。
- 帯の色を反転させる時（黒い帯に白文字など）は、office.css が文字色を !important で指定しているので、文字色を直接上書きせず、その帯の中だけ --kk-* 変数を切り替える。
- base.css 等で img の height:auto を外した場合、width/height属性のある画像は属性の高さで表示される。縦横比を指定する画像には height:auto を付ける。
- 比較ページ（compare/、元は _build/hub.html）でパターン①②③を切り替える。パターン③はデザインA/B/Cとも6ページすべて選べる（URL #p3-d1〜d3-ページ名）。比較ページの中では各ページ上部の第3パターン用の切替バーを出さない（html.in-hub）。パターンやページを増やした時は hub.html の PAGES・一覧・ラベルを一緒に直す。
- 写真を横に置く見出し（C）は、文字の幅を写真の手前で止める。site.css の .page-hero p.lead{max-width:640px} が .wrap>* より強いので、リードにも明示する。QAが「見出しの文字が写真に重なる」で検出する。

## 13. パターン②③の作り直し（2026-11-09〜。参考：② GTN 採用サイト／③ 日鉄パイプライン＆エンジニアリング）
- 方針：CMSのsectionを置き、見た目はCSS・動きはJSで作り込む（CSSとJSでできる範囲なら大胆に変えてよい）。HTMLの構造は変えない。
- 強い仕掛けを1つに絞って、サイト全体をそれで通す。型を少し変えるだけの改修はしない（「興味のない人が、ひとスクロールで今のサイトと違うと分かるか」で判断）。
  - ③：巨大な英字の見出し（Barlow Condensed）＋ 大きな角丸で切り抜いた写真 ＋ 太い縁取りを付けた写真 ＋ 背景の巨大な図形。図（断面図・イラスト）は使わない（2026-11-09 断面図は「意味が分からない」ため廃止。説明が要る図より、縁取りした実写の写真で見せる）。コンテンツは①（事業・進め方・施工実績・会社情報）＋②（ビジョン・働き方・人）のミックス。
  - ②：紺の大きな曲面（宣言文を載せる）＋ 巨大な英字（Montserrat）。流れは ビジョン → 入口（職種・募集要項）→ 会社 → 代表 → 働き方 → 人 → これから → 実際の仕事 → JOIN US。
- デザインの派生（B・C）は、ベースと同じHTML・同じ内容で、CSSだけで大胆に変える（微調整の派生は作らない）。②：B EDITORIAL／C CINEMA、③：B ASPHALT／C STRATA（③の派生名は当初の断面図の発想から来ているが、図は使っていない）。
  - ②の派生は p2n_build.py がベースを /pattern2/design-b|c/ に写して作る。写す時は href・src だけでなく style属性の url(...) のパスも直す（QAが「背景画像のパスが切れている」で検出）。
- ファイル：assets/n/p2.css・p2-b.css・p2-c.css、p3.css・p3-b.css・p3-c.css、n.js（スライド・カルーセル・表示アニメーション）、assets/fonts/display-en.css（英字フォントは自前で配信）。
- 派生のCSSは html[data-design="…"] から書く（ベースの html[data-pattern="…"] より弱いと、写真の高さなどが効かない）。
- 暗い地のデザイン（③B・②C）では、site.css・office.css が背景を白で固定しているカード類は白のまま、中の文字色（--kk-* と別名の --navy・--ink 等の両方）を濃い色に戻す。紺の帯の中は文字を白に。
- アニメーションは位置だけを動かし、透明にしない（文字が読めない瞬間を作らない）。動きを減らす設定では動かさない。
- 内容を減らしてデザインの差を出さない。QAが「パターン②③のTOPの本文量がパターン①のTOPの8割未満」を検出する。
- 背景の装飾（円・図形）は自分の section の中で切る（.n-sec・.m-sec は overflow:clip）。はみ出すと、後ろに続く section より前に描かれて隣の文字を隠す。カードの中の装飾は文字の後ろ（文字側に z-index）に置き、文字と重ならない位置に寄せる。
- 色の配分（2026-11-09 伊藤さんFB「ネイビーが強すぎる、ライムをもっと使ってよい」）：ボタン・タグ・カルーセルの操作・数字の面・宣言文の面など要所はライム（#A8C63A）、ライムの上の文字は紺（#1A2259）。白い文字はライムに載せない。紺の大きな面は、代表の分割面・フッターなど最小限にする。③Bの差し色は安全ベストの蛍光ライム、③Cのボタンもライム。
- パターン②もライムの上に文字を載せるため、配色は承認済みの基準配色で固定（配色パネルの色セットでは変えない）。
- ベースの色を変えたら、派生（特に暗い地の②C・③B）にも文字色が漏れていないかを必ずQAで確認する（ベースで紺にした文字が、暗い地の派生で読めなくなる）。

## 14. クライアント送付用（2026-11-10〜）
- 送付用は /client/ 以下に、元のページとは別のコピーとして置く（元のページ・比較ページには手を加えない）。例：/client/pattern2-a-top/（パターン②×デザインAのTOP）。
- 作り方：`python3 _build/client_build.py <サイトのフォルダ> client/<名前>`。リンクはすべて無効（href等を外す。「本文へ移動」だけ残す）、デモ用の部品（切替バー・確認用/公開イメージの切替・デモの注記）を外し、使う素材だけを assets/ に集める。
- /client/ はスナップショット。build.py では再生成しない（送付後に元のページを直しても、送った内容は変わらない）。更新して送り直す時だけ client_build.py を再実行する。

## 15. 日本語の見直し（2026-11-11 伊藤さんFB「サイトがところどころ変」「メインも」＝日本語）
- 文を書いたら、1行ずつ次を確認する：①文が最後まで終わっているか（「〜せずに。」「〜の、これから。」「〜から。」で切らない）②何を・誰がが分かるか（「守るために、変えていく」のような目的語のない文にしない）③言葉の組み合わせ（「個性を型にはめる」「土木を担う」×）④並列のねじれ（「〜し、〜し、〜ない会社へ」×）⑤同じ文をページ内で繰り返さない ⑥呼び方・用語の統一（社員／スタッフ、復旧舗装／舗装復旧）⑦語尾の統一（同じ並びのカードは揃える）⑧固有名詞・正式名称（「令和6年能登半島地震」に「年度」は付かない）⑨英字ラベルの意味と文法 ⑩ページ内に無い内容を指す文（「〜について話しています」）を書かない ⑪クライアントに見せて印象が悪い語（「衝突」等）や言い訳に読める注記を避ける。
- 送付用ページを作り直す前に、修正前の言い回しが残っていないかを検索で確認する。
